适用版本：v0.2.0。项目主页：[JOB HUNTING](../README.md)。

**DEVELOPED by @赛博老爸，本版本为开源版本，禁止商用。** 本项目为限制商用的源码公开作品，具体允许范围见 [LICENSE](../LICENSE)。

## 1. 先了解运行方式

系统运行在你的电脑上，浏览器是操作界面，本地 Node.js 服务负责保存资料、生成文件、采集岗位与连接邮箱。不需要购买服务器、域名，也不需要先开通 AI 服务。

| 你想做的事 | 所需条件 |
| --- | --- |
| 使用体验样例、保存档案、匹配、生成 DOCX 和准备草稿 | Node.js 22 或更新版本；首次安装项目依赖 |
| 采集招聘来源 | 电脑联网，来源页面允许访问且结构受支持 |
| AI 生成邮件或准备内容、辅助排列文件重点 | 在数据与设置顶部填写兼容接口、密钥与模型名称，保存后即时生效 |
| 同步真实收件箱 | 自己邮箱的 IMAP 配置与授权凭据 |
| 发送投递或回复 | SMTP 配置、显式启用真实发送，并完成相应内容确认 |

AI、邮箱和自动化均可先不配置。首次打开会看到明确标注的虚构样例；样例帮助熟悉界面，不能发送，也不是已经抓取到的真实职位。

## 2. 第一次启动

### Mac：下载并双击

1. 安装 **Node.js 22 或更新版本**，安装后重新打开终端，使 `node` 和 `npm` 命令生效。
2. 从仓库选择 **Code → Download ZIP**，完整解压到准备长期使用的目录；不要在压缩包内运行。克隆仓库也可以。
3. 打开项目目录，确认可以看到 `package.json`、`server`、`src` 和 `启动求职系统.command`。
4. 双击 `启动求职系统.command`。首次会安装缺失的依赖；GitHub 源码没有 `dist`，脚本会继续构建界面。
5. 浏览器自动打开后进入系统；没有自动打开时，访问 [http://127.0.0.1:4318](http://127.0.0.1:4318)。
6. 保留启动时的终端窗口。要退出服务，在该窗口按 `Control + C`；只关闭浏览器标签不会停止后台服务。

原始 v0.2 源码交付 ZIP 随附 `dist`，启动脚本会复用其中的构建文件。GitHub 自动生成的源码 ZIP 不含 `dist`，首次需构建；它不是免安装 Node.js 的独立 Mac 应用。

如果系统提示启动脚本没有执行权限，可在终端输入 `chmod +x `（末尾留一个空格），把 `启动求职系统.command` 拖进终端后按回车，再双击。也可直接采用下方终端方式。若 macOS 提示安全限制，请先核对下载来源，再按系统界面允许的方式打开。

### 终端方式

打开终端，输入 `cd `（末尾留空格），将解压后的**项目文件夹**拖入终端，按回车。确认当前目录中有 `package.json`，依次执行：

```bash
node --version
npm install
npm run build
npm start
```

第一条命令应显示 `v22` 或更高版本。依赖安装和构建完成后，打开 [http://127.0.0.1:4318](http://127.0.0.1:4318)。第一次使用不需要复制或填写 `.env`。

已使用 pnpm 的用户可以依次执行：

```bash
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

开发界面使用 `npm run dev`，访问 [http://localhost:5173](http://localhost:5173)。完整构建版本使用 `4318`，不要把两个地址混用。服务默认监听 `127.0.0.1`，手机不能直接通过电脑的局域网 IP 访问；手机截图展示的是响应式界面，不代表提供了手机远程服务。

## 3. 填写自己的求职档案

进入左侧 **求职档案**，将体验资料替换为自己的真实内容。

1. 填写姓名、联系邮箱，可选填作品集或个人主页。
2. 填写目标岗位、意向城市、行业和期望月薪。月薪单位是人民币 **K / 月**，例如 `20` 表示 20,000 元；下限不能高于上限。
3. 填写工作年限、最高学历、核心技能与个人简介。多个城市、行业或技能用顿号或逗号分隔。
4. 在 **简历内容** 粘贴教育、工作、项目经历与成果，或点击 **选择文本** 导入 TXT / Markdown。文本文件最大 1 MB，简历正文最多 40,000 字符。
5. 需要发送原始排版文件时，点击 **上传附件**；支持 PDF / DOCX / TXT / MD，最大 5 MB。
6. 点击 **保存档案**，使文字修改生效并重新计算匹配。

**原始附件与简历正文是两份不同用途的资料。** 上传 PDF / Word 不会自动提取文字；用于匹配和求职文件的文字仍需单独维护。上传、替换或删除附件会立即更新附件及档案版本。

保存新档案不会自动重写旧材料或旧草稿。更新后，请在求职文件中重新生成，在投递详情中使用 **按最新档案重写**，再次核对附件并审核。使用示例档案生成的内容不能因为后来改了姓名就直接发送。

## 4. 采集岗位，建立自己的岗位库

### 启用现有来源

1. 进入 **数据与设置 → 岗位来源**。
2. 查看来源卡片，开启需要的来源；点击 **保存** 保存开关，或点击 **同步** 保存并采集该来源。
3. 到 **岗位库** 采集已启用来源，查看结果与错误提示。
4. 使用搜索和地区、来源、学历、薪资、信息类型、报名状态等条件缩小范围。
5. 打开记录中的原文链接，核对招聘单位、职责、资格、报名方式和截止日。

岗位库保存全部成功采集的真实信息，不要求它们先匹配你的档案。低分、不符合、未明确条件、已过已知截止日的记录也会保留；其中公告与已截止岗位不能直接建立投递。截止日未知表示需要核对，不表示长期有效。

**岗位库**用于查看真实库存；**发现岗位**用于按个人条件筛选与理解匹配。学历、经验等硬条件单独显示，高偏好分不会抵消不符合的硬条件，分数也不是录用概率。

### 理解来源范围

| 来源 | 每次读取范围 |
| --- | --- |
| 国家大学生就业服务平台 | 一页最多 20 个公开职位及详情 |
| 上海市人社局 | 最新 12 篇公告，展开明确的正文岗位和 HTML 表格 |
| 腾讯官方招聘 | 一页最多 10 个职位及详情 |
| 复旦大学人事处 | 派遣制用工公开目录当前一页，保留为待核对公告 |
| Remotive | 公开远程职位 API；至少间隔 6 小时，数据注明原站 24 小时延迟 |
| Greenhouse | 填写具体企业公开招聘页的 Board Token 后读取该企业公开职位 |

“官方入口 · 不支持同步”仅是访问官网的快捷链接。复旦来源不代表全校招聘；平台上的岗位也不代表都是事业编或公务员岗位。附件表格、图片或无法明确拆分的多岗位招聘会保留为公告，需打开官网继续阅读。

2026-11-14 交付验证的四个中国来源共取得 77 条信息（59 个岗位、18 篇公告），其中 14 条已过已知截止日仍保留。此数字用于说明当次验证，不随源码分发，也不是你每次都会采集到的数量。完整证据见 [验证记录](VERIFICATION.md) 与 [来源说明](SOURCES.md)。

### 添加当地人社、学校或企业目录

在 **数据与设置** 顶部的 **添加当地人社、学校或企业招聘目录** 表单填写：

| 字段 | 填写方法 |
| --- | --- |
| 来源名称 | 能辨认机构和目录的名称，例如“某大学人事处 · 公开招聘” |
| 来源分类 | 选择人社官方招聘、高校招聘或企业招聘 |
| 公开招聘目录网址 | 从机构官网核实的 HTTPS 招聘列表页，使用标准 443 端口 |
| 来源所在地区 | 可选；它是来源标签，不代表公告内所有岗位的实际工作地点 |

点击 **添加采集来源** 后，在来源卡片同步。名称和分类由你填写，系统不会据此认证机构身份。

通用连接器只读一页公开静态 HTML 目录，最多收录 30 条同域公告；不翻页、不读详情、不解析附件、不登录，也不执行网页脚本。收录结果全部是待核对公告，学历、薪资、邮箱等保持未知。只有 JavaScript 才显示的列表、验证码页面、登录系统和禁止自动访问的网站不适用，可在官网查找后手动导入。详见 [自定义来源说明](CUSTOM-SOURCES.md)。

### 导入已有岗位

进入 **数据与设置 → 导入你找到的岗位**，下载 JSON 模板填写，或上传 JSON / CSV 文件、粘贴数据。点击 **检查数据**，确认预览后点击 **导入岗位**。

每次最多 500 条，上传文件最大 5 MB。`title`（岗位）和 `company`（公司）必填；CSV 的 `skills`、`description`、`requirements` 多项使用 `|` 分隔。薪资单位为税前人民币千元/月，未知数值用 JSON `null` 表示，不要将未知币种硬换算成人民币。保留原文链接；空邮箱不会被自动补造。

导入入口用于岗位数据，不能用来恢复整个工作区导出文件。完整恢复方法见第 9 节。

## 5. 生成并下载求职文件

1. 进入 **求职文件**，选择目标岗位。
2. 点击 **生成这份求职材料**。
3. 分别查看 **岗位简历、求职信、证据清单**，检查事实、缺项和明显差距。
4. 切换到要下载的材料类型，点击 **Word 文档**、**Markdown** 或 **打印版 HTML**。
5. 需要 PDF 时，打开下载的 HTML，在浏览器选择 **打印 → 另存为 PDF**。

Word 下载是真实可编辑 DOCX，三种材料分别下载。简历和求职信以档案事实构建，未提供的公司经历、学校、证书和成果不会自动补写；证据清单的“档案有记录”也不等同于经历已经核实。

启用 AI 后，求职文件只允许模型排列已有技能和核对事项；错误或不合规结果会回退本地规则。材料保存生成时的档案版本，出现“档案已更新”提醒时，应点击 **根据最新档案重新生成**。更多格式与事实边界见 [求职文件说明](DOCUMENTS.md)。

## 6. 准备与发送投递

### 单个岗位

在具体岗位准备申请后，进入 **投递管理** 打开投递详情。核对收件人、主题、求职信全文与 **简历附件**，必要时编辑并保存。

附件优先使用你为此申请选定的当前岗位定制简历 DOCX；未绑定定制材料时使用上传的原始简历，再没有才使用档案的 `resume.txt`。如果原始附件和定制材料都有，投递详情中的实际选择才决定发送哪份。

点击 **已审核，加入待发送** 仅加入队列。配置真实发送后，点击 **发送投递**，再次核对确认框，再点击 **确认发送** 才会通过邮箱发送。没有公开招聘邮箱时，按照官网申请方式操作；不要把咨询、监督或举报邮箱当成投递地址。

### 每批 1–30 个岗位

1. 在岗位库选择 1–30 个具体岗位，批量准备草稿；每项会生成对应定制简历。
2. 查看逐项准备结果。某个岗位失败时查看原因，其余已成功项仍可继续。
3. 在投递管理逐封检查收件人、完整正文和实际附件，逐封勾选审核确认。
4. 审核通过后，明确启动发送，再次逐封核对并确认。
5. 查看任务进度与逐封结果；需要停止时点击 **取消剩余任务**。

修改正文、收件人、附件或档案会使旧审核失效，需重新审核。定制文件必须属于同一岗位及当前档案版本；未展开公告、已截止岗位、示例内容或无有效邮箱的记录不能直接发出。

系统依次发送并记录成功、失败、跳过或取消原因。取消阻止后续尚未开始的邮件，无法撤回已经交给 SMTP 的邮件。服务重启后未完成批次标为中断，不会自动续发。若显示发送中或结果待核对，请先检查发件邮箱，避免重复投递；SMTP 接受也不表示对方已阅读。

### 自动处理

在 **数据与设置 → 有边界的自动化** 配置。各开关默认关闭；自动准备只影响草稿准备，不影响真实岗位进入岗位库。

- **定时同步岗位与邮件**：按保存的间隔检查已启用来源；邮件同步还需要 IMAP，各来源最低间隔仍生效。
- **自动准备与投递**：按匹配条件生成草稿；实际发送只处理人工审核后加入待发送、且收件人在精确邮箱白名单内的记录。
- **自动回复收件确认**：只对白名单来信发送固定确认，不承诺面试时间或接受录用条件。

白名单每行填写一个完整邮箱。批量投递、自动投递与自动回复共享每日发送额度，默认 5 次；留空白名单不会自动发送。明确手动启动的批次不要求自动投递开关或白名单，但仍要求真实发送配置、内容确认与剩余额度。

所有任务仅在本地服务运行时执行，关机、休眠或停止终端服务后没有云端接续。

## 7. 配置 AI 和自己的邮箱

### 在设置页连接 AI

1. 打开 **数据与设置**，找到页面顶部的 AI 配置卡片。首次连接无需编辑 `.env`。
2. 在服务商控制台取得接口基址、API 密钥和你有权调用的模型名称；接口必须兼容 **OpenAI Chat Completions**。API 调用是否收费、额度与价格以该服务商规则为准。
3. 填写 **Base URL**。例如服务商给出的基址为 `https://api.openai.com/v1`，就填写这个基址；不要在后面附加 `/chat/completions`。远程地址使用 HTTPS；本机服务可使用 `http://127.0.0.1:端口/v1` 等回环地址，具体端口和路径以实际服务为准。
4. 在 **API Key** 输入自己的密钥，在模型字段填写服务商实际支持的模型名称。模型名不是随意起的备注，没有隐藏的默认模型可代替。
5. 点击 **测试连接**。系统会用当前表单发起一次真实模型请求并显示结果；这会产生 API 用量，测试不保存配置，也不生成申请或发送邮件。
6. 测试通过后保存。配置立即用于后续生成，无需重启服务；只测试不保存，其他页面仍使用原来保存的配置。
7. 到 **求职文件** 重新生成材料，或到投递详情点击 **按最新档案重写**，确认生成方式。已保存的旧材料、正文不会因为更换模型而自动改写。

同一份 AI 配置用于求职文件中的已有技能与核对事项排序、投递邮件草稿及重写、邮件回复草稿、笔试和面试准备。简历简介与经历仍来自真实档案，不会凭空补写学历、公司经历或成果；匹配分始终由本地规则计算。没有配置、请求失败或结果校验失败时，界面会使用并标明本地模板或规则。

**密钥如何修改：**保存后，页面只显示是否已有密钥，不会把原值填回输入框。Base URL 不变时，输入框留空会保留已保存的密钥，可直接修改模型后测试、保存。改了 Base URL 就要重新输入用于新地址的密钥；系统不会把旧服务的密钥自动带到新地址。要停用 AI，点击 **清除密钥**，再点击 **确认清除密钥**；确认后立即保存清除结果，无需再点保存。留空不等于清除。

**配置保存在哪里：**AI 配置由本地服务写入 `data/ai-config.json`，权限为 `0600`，不会放进工作区导出、日志或 Git，也不会返回已保存密钥。它是本机配置文件，并非加密保险箱，备份整个 `data` 时也会备份其中的密钥。

**已经用过 `.env` 的用户：**未保存界面配置时，系统仍使用 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL` 作为回退。保存界面配置后，以本地配置为准；即使明确清除了本地密钥，也不会重新启用 `.env` 中的旧值。仅通过 `.env` 调整 AI 的兼容方式仍需要重启，界面保存无需重启。

连接测试成功只代表当前地址、密钥和模型完成了当次请求，不保证后续请求永远成功或生成内容正确。实际生成时，相关岗位、档案或邮件上下文会发送到指定服务。求职文件排序请求不发送独立的姓名、联系邮箱字段，但简介等文本若自行包含个人资料，仍会随请求发送。

### SMTP 发信与 IMAP 收信

邮箱配置仍通过 `.env` 完成，不受顶部 AI 卡片控制。仅首次配置、且还没有 `.env` 时，在项目根目录执行：

```bash
cp .env.example .env
```

然后用纯文本编辑器编辑 `.env`；Mac Finder 默认可能不显示点开头的文件，可按 `Command + Shift + .` 切换显示。已有 `.env` 时直接编辑，勿再次复制覆盖。邮箱配置保存后需停止并重启服务，再到 **数据与设置 → 连接状态** 查看状态。

按邮箱服务商给出的参数填写；部分邮箱需先启用 SMTP / IMAP 并创建应用专用密码或授权码。

```dotenv
SMTP_HOST=你的发信服务器
SMTP_PORT=587
SMTP_USER=你的邮箱账号
SMTP_PASS=你的授权凭据
SMTP_FROM=你的发件邮箱

IMAP_HOST=你的收信服务器
IMAP_PORT=993
IMAP_USER=你的邮箱账号
IMAP_PASS=你的授权凭据

ENABLE_OUTBOUND=false
```

端口以服务商文档为准；示例中的 `587` 和 `993` 不是所有服务的通用配置。只需收件可以只配 IMAP；只需发件可以只配 SMTP。`ENABLE_OUTBOUND=false` 会阻止所有真实外发；准备好后显式改为 `true` 并重启，仍需在界面确认发送。

邮箱连接状态“已启用”表示配置项满足本地检查，不是远程邮箱已经认证成功。原 v0.2 交付验证未使用真实邮箱或模型凭据，也未向招聘方发送邮件；真实连接、服务商限制与最终收发结果需要在你的本地账号上验证。

`.env` 与 `data/ai-config.json` 都是本机私有配置。仓库已忽略 `.env` 与 `data/`，但发布自己的 ZIP 或附件时仍要检查；不要把密钥、完整配置文件和个人工作数据放进公开 Issue。

## 8. 邮件跟进与面试准备

在 **邮件助手** 点击 **同步收件箱**。系统读取最近 30 天中最多 100 封邮件，单封不超过 1 MB，单次总量最多 8 MB；邮件附件不执行、不持久保存。分类为关键词辅助判断，应以招聘方正文为准。

选择来信后，可点击 **生成回复草稿**，按真实安排补充内容、保存草稿。需要回复时点击 **发送回复**，检查收件人与正文后确认。示例邮件不能发送；自动回复仅处理最近 7 天内符合条件的白名单来信，并跳过检测到的自动邮件。

在 **面试准备** 中选择目标岗位、面试或笔试阶段，填写轮次、通知要求或希望练习的问题，点击 **生成专属准备清单**。结果可复制到自己的笔记。个人项目、成果与数字需要你用真实经历补充；系统不代替你接受招聘安排。

## 9. 数据、备份与更新

默认工作数据位于项目内：

```text
data/state.json     档案、岗位、材料、申请、批次、邮件与设置
data/attachments/   上传的原始简历文件
data/ai-config.json 设置页保存的 AI 配置与密钥
.env                邮箱 / 端口 / 数据目录，以及兼容的 AI 回退配置
```

这些资料保存在本机，工作区数据是明文；界面导出的 JSON 仍可能含简历、联系方式与邮件，应按私人资料保管。

**轻量导出**：在数据与设置点击 **导出工作区**。JSON 不含原始附件二进制、AI 配置密钥或 `.env` 密钥，不能代替完整文件夹备份。

**完整备份**：停止服务，复制整个 `data` 目录到私人备份位置；其中的 `ai-config.json` 含 AI 密钥，备份也应私下保管。如需保留邮箱等连接设置，单独妥善备份 `.env`。设置了 `DATA_DIR` 时，备份实际指定目录。不要让两个服务进程同时写入同一目录。

**恢复或换版本**：停止服务，保留原目录备份，把自己的完整数据目录和本机 `.env` 放到新项目对应位置，或继续使用原 `DATA_DIR`，再安装依赖并构建启动。先使用兼容版本恢复；不要直接用新文件覆盖唯一备份。当前界面没有完整工作区恢复按钮。

更新源码后，应再次运行 `npm install` 和 `npm run build`，再启动。双击脚本只在依赖目录或构建文件缺失时安装、构建，不会因为你刚替换了源码就自动重建已有 `dist`。

## 10. 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 提示没有 Node.js 或版本过低 | 安装 Node.js 22 或更新版本，重新打开终端；运行 `node --version` 核对 |
| 找不到 `package.json` | 终端不在项目根目录；进入完整解压后的项目文件夹再执行命令 |
| 首次安装很慢或失败 | 检查网络与终端报错，确认 npm 能下载依赖，修复原因后重试 `npm install`；不要把失败当成已启动 |
| 页面打不开或“无法连接本地服务” | 检查启动终端仍在运行；正式版打开 `4318`，开发界面打开 `5173`；确认构建已完成 |
| 提示 `EADDRINUSE` | 端口被占用；先确认是否已有本系统运行，或停止冲突服务。可在 `.env` 修改 `PORT` 后用完整构建版本启动；开发代理默认使用 `4318` |
| 下载后只有样例，没有 77 条岗位 | 源码不包含验证人员的本地工作区；进入数据与设置启用来源，再到岗位库采集 |
| 发现岗位没有合适结果 | 检查真实档案与筛选条件；到岗位库看全部真实记录。匹配条件不会阻止采集入库 |
| 同步失败、没有权限、被限频 | 查看来源提示；等待最低间隔或到官网核对。登录、验证码、robots 拒绝、403 和重定向限制不会被绕过 |
| 自定义网址提示非公网地址 | 检查网址及代理 DNS；Fake-IP 可能返回保留地址。连接器不会放宽公网检查，可改用手动导入 |
| 学历、薪资、截止日或邮箱显示未知 | 来源未明确提供或无法可靠解析；打开原文核对，不要将未知当作“无限制” |
| 上传 PDF / Word 后档案文字仍为空 | 当前只保存原始附件，需另行提取并粘贴简历文字，再保存档案 |
| 审核后又变回草稿、提示材料过期 | 档案、正文或附件已变化；按最新档案重新生成或保存，检查实际附件后重新审核 |
| 无法发送，或按钮不可用 | 检查真实档案、非示例记录、有效收件人、岗位截止日、材料版本、SMTP、真实发送开关及额度；自动发送还需白名单 |
| AI 保存成功，但生成还是失败或回退模板 | 保存不等于连接通过；用当前表单测试，检查服务商地址、实际模型权限、额度与返回错误。API 可能收费 |
| AI 测试通过，其他页面仍使用旧模型 | 测试不会保存配置；保存后重新生成文件或草稿，旧内容不会自动改写 |
| 刷新后 API Key 输入框为空 | 已保存密钥不回显；地址不变且显示已有密钥时，留空会保留。要删除，点击“清除密钥”后再点“确认清除密钥”，立即生效 |
| 更换 Base URL 后要求重新填写密钥 | 旧密钥只允许用于原地址；填写新服务的密钥，再测试、保存 |
| 清除了本地密钥，`.env` 的 AI 也未启用 | 本地配置优先，明确清除会停用 AI，不会悄悄回退旧密钥。要重新连接，请在设置页重新填写并保存 |
| 邮箱显示已启用但收发失败 | 核对服务商地址、端口、协议授权、应用密码及服务商限制；配置完整不等于远端登录成功 |
| 发送结果待核对或重启后批次中断 | 先到发件邮箱核对是否已发送，避免重复投递；系统不会自动续发中断批次 |
| 关闭页面后任务是否继续 | 浏览器关闭但服务仍运行时可以继续；停止服务、休眠或关机后不继续 |
